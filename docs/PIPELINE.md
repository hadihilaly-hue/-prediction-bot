# Paper pipeline audit

Code-path notes for the scheduled paper workflow on the branch containing PR #28. External observations below (Odds API headers/response, Kalshi `/series` and `/markets` fields) were checked against the live public APIs on 2026-10-23 at about 07:00 UTC.

## Scheduler and data sources

| Trigger | Work performed |
|---|---|
| `17 3,11,19 * * *` (UTC) | Run `book_scanner`, then sportsbook strategies if the Odds API key is set. |
| `47 * * * *` and `17 0-2,4-10,12-18,20-23 * * *` (UTC) | Run `book_scanner` only; these interleaved cron slots make a half-hour cadence. |
| `workflow_dispatch` | Run both scanner and sportsbook strategies if the Odds API key is set. |

The workflow runs `pbot paper` once per scheduled cycle in `PBOT_MODE=paper`, against Kalshi's public production API, with `PBOT_PAPER_DB_PATH=ledger/paper.sqlite`. Its sportsbook invocation covers `KXNFLGAME`, `KXNCAAFGAME`, `KXNBAGAME`, `KXNCAAMBGAME`, `KXNHLGAME`, `KXMLBGAME`, `KXEPLGAME`, `KXLALIGAGAME`, `KXUCLGAME`, `KXSERIEAGAME`, `KXBUNDESLIGAGAME`, `KXLIGUE1GAME`, `KXUELGAME`, `KXUECLGAME`, `KXMLSGAME`, `KXLIGAMXGAME`, `KXUFCFIGHT`, `KXMASTERS`, `KXPGA`, `KXUSOPEN`, and `KXTHEOPEN` (`.github/workflows/paper.yml:paper`). `OddsClient` maps supported series to The Odds API sport keys (`src/prediction_bot/odds.py:KALSHI_SERIES_TO_SPORT`, `KALSHI_SERIES_TO_OUTRIGHT`); WNBA has a mapping but is not in this workflow's series list.

Workflow settings include `PBOT_MIN_EDGE=0.01` (one cent after fees), `PBOT_ODDS_RUNS_PER_DAY=3`, `PBOT_KILL_SWITCH` defaulting to `false`, `PBOT_MAX_DAILY_LOSS` defaulting to `$50`, `PBOT_KALSHI_API_BASE=https://api.elections.kalshi.com/trade-api/v2`, and the `PBOT_ODDS_API_KEY` Actions secret (`.github/workflows/paper.yml:paper`). `PBOT_ODDS_RUNS_PER_DAY` and the shared quota determine a variable per-run request budget; calls are prioritized by `SportsbookArbStrategy._prioritised` and constrained by `OddsPacer.start_run` / `per_run_budget` (`src/prediction_bot/cli.py:paper`, `src/prediction_bot/odds.py:OddsPacer.start_run`, `per_run_budget`). The workflow comment's 372-requests/month estimate assumes four sports per run; actual requests depend on the budget, eligible feeds, and cache hits.

`OddsClient.odds` calls The Odds API v4 `/sports/{sport}/odds` with `regions=us,eu`, one `markets` value (`h2h` for games or `outrights` for tournaments), `oddsFormat=decimal`, and the configured bookmaker list (`src/prediction_bot/odds.py:OddsClient.odds`, `src/prediction_bot/config.py:Settings.odds_bookmakers`). The requested books are Pinnacle, Circa, BetOnline (`betonlineag`), DraftKings, and FanDuel. Strategies share one client, and its response memo lasts 60 seconds (`src/prediction_bot/cli.py:_strategies`, `src/prediction_bot/odds.py:OddsClient.MEMO_TTL_S`, `OddsClient.odds`).

## Processing path

1. **Fetch Odds API data.** `SportsbookArbStrategy.evaluate` groups Kalshi markets by event, skips events that fail its lead-time prefilter, then obtains h2h or outright events through `games_for` / `outrights_for` (`src/prediction_bot/strategies/sportsbook_arb.py:SportsbookArbStrategy.evaluate`, `games_for`, `outrights_for`). `OddsClient.odds` memoizes by sport, market, and bookmaker list; the budget counts actual requests, not events (`src/prediction_bot/odds.py:OddsClient.odds`).
2. **Map teams and fixtures.** `best_team` scores normalized names with token-set Jaccard-like overlap, token fuzzy matching via `SequenceMatcher`, `_ALIASES`, and `SUBSET_SCORE=0.34`; ties are rejected (`src/prediction_bot/odds.py:_normalise`, `_tokens`, `_same_token`, `team_match_score`, `best_team`). `_match_game` requires matching team names and uses the nearest game start within 18 hours of `expected_expiration_time`, or within four days of `close_time` as a fallback (`src/prediction_bot/strategies/sportsbook_arb.py:SportsbookArbStrategy._match_game`, `_start_gap`). Outrights use `_match_tournament` with a 10-day window (`src/prediction_bot/strategies/sportsbook_arb.py:SportsbookArbStrategy._match_tournament`). `_early_enough` defaults to a 72-hour lead, anchored first to expected expiration (then supplied `commence_time`, or close time for markets without a commence time); this is not a kickoff guard (`src/prediction_bot/strategies/sportsbook_arb.py:SportsbookArbStrategy._early_enough`, `src/prediction_bot/config.py:Settings.min_lead_hours`).
3. **Devig and combine books.** `devig` applies multiplicative normalization of implied probabilities only. `consensus` applies it per bookmaker, then computes a weighted average by outcome; `BOOK_WEIGHTS` are Pinnacle 3, Circa 3, BetOnline 2, and 1 for other configured books (`src/prediction_bot/odds.py:devig`, `consensus`, `BOOK_WEIGHTS`). The same `consensus` handles outright fields with a 90% coverage check (`src/prediction_bot/odds.py:consensus`, `MIN_FIELD_COVERAGE`).
4. **Fetch Kalshi market data.** `cli._fetch` calls `KalshiClient.get_markets`; `parse_market` reads `yes_bid_dollars`, `yes_ask_dollars`, `yes_bid_size_fp`, and `yes_ask_size_fp` into a `Quote` (`src/prediction_bot/cli.py:_fetch`, `src/prediction_bot/venues/kalshi.py:KalshiClient.get_markets`, `parse_market`). The strategy's quote is top-of-book only. It does not use `last_price`; the parsed `Market` has no last-price field, and `parse_orderbook` reduces orderbook data to the best YES bid / YES ask and their sizes (`src/prediction_bot/venues/kalshi.py:parse_market`, `parse_orderbook`, `src/prediction_bot/models.py:Quote`).
5. **Calculate edge / entry price.** `Strategy.make_signal` compares side fair value to the entry price minus `fee_for` on one contract, then enforces `min_edge` (`src/prediction_bot/strategies/base.py:Strategy.make_signal`, `src/prediction_bot/models.py:fee_for`). Taker price is the side's ask (`Quote.ask_for`); maker is the side's bid plus $0.01 when it remains below the ask, otherwise it falls back to the ask as taker (`src/prediction_bot/models.py:Quote.ask_for`, `Quote.bid_for`, `src/prediction_bot/strategies/base.py:Strategy.make_signal`). The scheduled `$0.01` threshold overrides the `$0.03` config default (`.github/workflows/paper.yml:paper`, `src/prediction_bot/config.py:Settings.min_edge`).
6. **Size and risk-check.** `Strategy._size` floors `$25 / price`, caps at 100 contracts, then caps taker size at displayed ask-side size; maker size is not depth-capped (`src/prediction_bot/strategies/base.py:Strategy._size`, `Strategy.make_signal`, `src/prediction_bot/config.py:Settings.max_order_notional`, `max_position_contracts`). Before sizing is acted on, `make_signal` rejects a side when its interacting top-of-book size is below `min_book_depth` (default 10); for maker that is displayed bid-side size (`src/prediction_bot/strategies/base.py:Strategy.make_signal`, `src/prediction_bot/config.py:Settings.min_book_depth`). There is no Kelly sizing (`src/prediction_bot/strategies/base.py:Strategy._size`).
7. **Paper fill.** `Engine._act` records every accepted paper signal as a fill at exactly `Signal.limit_price` (ask or maker bid + $0.01); maker orders do not wait for a later trade or quote to fill. Fee is `fee_for(price, count, multiplier)`, with the configured taker or maker multiplier and rounding up to a cent (`src/prediction_bot/engine.py:Engine._act`, `_fee_multiplier`, `src/prediction_bot/models.py:fee_for`). Settings use flat multipliers 0.07 / 0.0175 (`src/prediction_bot/config.py:Settings.taker_fee_multiplier`, `maker_fee_multiplier`).
8. **Ledger and settlement.** SQLite tables are `signals`, `fills`, `settlements`, `halts`, `cash`, `markets`, `runs`, and `odds_snapshots` (`src/prediction_bot/paper/ledger.py:SCHEMA`). `Engine.run_cycle` saves fetched consensus through `Ledger.record_consensus`; `Ledger.record_signal`, `record_fill`, and `record_run` persist signals, fills, and cycle summaries (`src/prediction_bot/engine.py:Engine.run_cycle`, `src/prediction_bot/paper/ledger.py:Ledger.record_consensus`, `record_signal`, `record_fill`, `record_run`). `Engine.settle_open_positions` re-fetches unresolved markets and calls `Ledger.settle` when Kalshi supplies a result (`src/prediction_bot/engine.py:Engine.settle_open_positions`, `src/prediction_bot/paper/ledger.py:Ledger.settle`).
9. **Stops, reporting, and dashboard.** `Engine.halt_reason` applies the UTC-day realized-loss drawdown limit and latches a halt; the kill switch blocks new entries (`src/prediction_bot/engine.py:Engine.halt_reason`, `src/prediction_bot/paper/ledger.py:Ledger.record_halt`, `halt_for_day`). In paper mode, `Engine._exposure` and `_admissible` count open exposure per strategy, including same-outcome equivalents; `Ledger.position_count` filters by strategy. Thus `sportsbook_arb` and `underdog_value` can each stack exposure on the same game, as recorded in the audit facts (`src/prediction_bot/engine.py:Engine._exposure`, `_admissible`, `src/prediction_bot/paper/ledger.py:Ledger.position_count`). CLI `report`, `predictions`, and `dashboard` use ledger performance/trades/signals (`src/prediction_bot/cli.py:report`, `predictions`, `dashboard`; `src/prediction_bot/paper/ledger.py:Ledger.performance`, `predictions`, `trades`). The workflow commits `paper.sqlite`, run/report/prediction outputs, and a self-contained `index.html` to `paper-ledger`; README documents serving that branch with GitHub Pages (`.github/workflows/paper.yml:paper`, `README.md:Scheduled paper trading (GitHub Actions)`, `src/prediction_bot/dashboard.py:dashboard_data`, `render_dashboard`).

## Timestamp audit

| Timestamp source | Clock and timezone | Notes |
|---|---|---|
| `Signal.created_at` | `datetime.utcnow()`, naive UTC | Serialized without a timezone marker by `Ledger.record_signal`; **naive** (`src/prediction_bot/models.py:Signal.created_at`, `src/prediction_bot/paper/ledger.py:Ledger.record_signal`). |
| Fill `created_at`, settlement `settled_at`, consensus `created_at`, run `ran_at` | Default `datetime.utcnow()`, naive UTC | `Ledger.record_fill`, `settle`, `record_consensus`, and `record_run` each create a naive UTC timestamp unless a caller supplies `at`; all defaults are **naive** (`src/prediction_bot/paper/ledger.py:Ledger.record_fill`, `settle`, `record_consensus`, `record_run`). |
| Odds `commence_time` | Provider ISO-8601 string; preserved as received | `ConsensusOdds` and `Ledger.record_consensus` store/pass it through; `_early_enough` and `_start_gap` parse it with `datetime.fromisoformat` after replacing `Z` with `+00:00`. An input without an offset would parse naive; no normalization/validation is applied (`src/prediction_bot/odds.py:ConsensusOdds`, `consensus`, `src/prediction_bot/strategies/sportsbook_arb.py:SportsbookArbStrategy._early_enough`, `_start_gap`, `src/prediction_bot/paper/ledger.py:Ledger.record_consensus`). Odds `bookmakers[].last_update` and `markets[].last_update` are not parsed or stored by this code (`src/prediction_bot/odds.py:consensus`). |
| Kalshi `close_time`, `expected_expiration_time` | ISO-8601 parsed by `_ts`; offset-aware when input has `Z` or an offset | `_ts` converts `Z` to `+00:00` and calls `datetime.fromisoformat`; an input without an offset remains naive (`src/prediction_bot/venues/kalshi.py:_ts`, `parse_market`). |
| Quota and strategy lead-time comparisons | Aware UTC wall clock | `run_share`, `_prioritised`, `_early_enough`, and `Engine.halt_reason` use `datetime.now(timezone.utc)`; the halt day is UTC (`src/prediction_bot/odds.py:run_share`, `src/prediction_bot/strategies/sportsbook_arb.py:SportsbookArbStrategy._prioritised`, `_early_enough`, `src/prediction_bot/engine.py:Engine.halt_reason`). |
| Dashboard / Markdown report generation | Aware UTC wall clock | `dashboard_data` and `predictions_markdown` emit UTC ISO/display timestamps (`src/prediction_bot/dashboard.py:dashboard_data`, `src/prediction_bot/cli.py:predictions_markdown`). |
| Kalshi request-signing header | Unix epoch milliseconds (UTC) | `KalshiSigner.headers` uses `time.time()` (`src/prediction_bot/venues/kalshi_auth.py:KalshiSigner.headers`). |
| Odds response memo | Monotonic elapsed-time clock; not a wall timestamp | `OddsClient.odds` uses `time.monotonic()` for its 60-second TTL (`src/prediction_bot/odds.py:OddsClient.odds`). CLI log `%(asctime)s` uses the process local timezone; the workflow does not set one explicitly (`src/prediction_bot/cli.py:_main`). |

## Odds API facts

The provider is The Odds API v4. The free-tier quota is 500 requests/month. The recorded quota check was 341 used / 159 remaining at 2026-10-23 07:00 UTC; one NFL sample request cost one credit, verified by `x-requests-last: 1`. `OddsClient.odds` requests `regions=us,eu`, one market per API call (`h2h` or `outrights`), decimal odds, and the five configured books (`src/prediction_bot/odds.py:OddsClient.odds`, `src/prediction_bot/config.py:Settings.odds_bookmakers`).

The NFL response sample contained 27 events and these book counts: DraftKings 27, FanDuel 27, BetOnline 13, Pinnacle 13, Circa 0. `commence_time`, `bookmakers[].last_update`, and `markets[].last_update` were present in that sample (;). The consensus code consumes odds/outcomes and does not use bookmaker update timestamps (`src/prediction_bot/odds.py:consensus`).

The Odds API `/odds` response includes live events for games already started unless a commence-time filter is supplied; `OddsClient.odds` passes no such filter (`src/prediction_bot/odds.py:OddsClient.odds`). The returned started-game odds are consistent with the Edmonton and Auburn ledger rows in the verified audit, but the current code has no in-play detector (`src/prediction_bot/strategies/sportsbook_arb.py:SportsbookArbStrategy.evaluate`).

## Kalshi facts

Observed public series metadata (`fee_type` / `fee_multiplier`) differs by series:

| Series | `fee_type` | `fee_multiplier` |
|---|---|---:|
| NFL, NCAAF, NBA, NCAAMB, NHL, EPL, UCL, LALIGA | `quadratic_with_maker_fees` | 1 |
| MLB | `quadratic_with_maker_fees` | 0.5 |
| MLS, UFC | `quadratic` (no maker fee) | 1 |

The code does not fetch or apply per-series fee metadata: `Settings` supplies flat 0.07 taker and 0.0175 maker multipliers and `Engine._fee_multiplier` selects only by entry style. Consequently it overstates MLB fees under the observed 0.5 multiplier and charges a maker fee for MLS/UFC, which the observed `quadratic` series do not have (`src/prediction_bot/config.py:Settings`, `src/prediction_bot/engine.py:Engine._fee_multiplier`,).

The observed `occurrence_datetime` equals `expected_expiration`, not event start. `expected_expiration_time` examples were about three hours after start: MLB SDMIL 23:00 vs 20:00 UTC start, NFL KCLV 23:25 vs 20:25 UTC kickoff, and TEXOKLA 22:30. The code parses `expected_expiration_time` as `Market.expected_expiration`; `close_time` is a separate later market-close value and is used as a fallback for matching/lead-time checks (`src/prediction_bot/venues/kalshi.py:parse_market`, `src/prediction_bot/strategies/sportsbook_arb.py:SportsbookArbStrategy._match_game`, `_early_enough`).

For MLB, observed `rules_primary` included a scheduled start-time string (e.g. “originally scheduled for Oct 4, 2026 at 4:00 PM EDT”); NFL, NCAAF, NHL, and MLS examples gave date only. Settled markets also expose candlesticks at `GET /series/{s}/markets/{t}/candlesticks?start_ts&end_ts&period_interval=60`, with yes-bid/yes-ask OHLC, price, volume, and open interest, usable for historical CLV.

## Known gaps vs the brief

- No kickoff guard; `_early_enough` is a 72-hour lead-time gate, not a start-time buffer (`src/prediction_bot/strategies/sportsbook_arb.py:SportsbookArbStrategy._early_enough`).
- Team association is fuzzy token matching rather than exact alias mapping (`src/prediction_bot/odds.py:best_team`, `team_match_score`).
- Paper exposure is per strategy, allowing both sportsbook strategies to stack the same outcome (`src/prediction_bot/engine.py:Engine._exposure`, `_admissible`).
- Fees are not series-specific (`src/prediction_bot/engine.py:Engine._fee_multiplier`).
- One devig method (multiplicative) is implemented (`src/prediction_bot/odds.py:devig`).
- CLV estimates depend on stored Kalshi candles and Odds API consensus snapshots; small entry-window samples are descriptive, not trading evidence.

## Entry-window shadow CLV

Entry-window decisions are grouped by decision-time lead into `72h+`, `24-72h`, and
`2-24h` windows. The dashboard reports the v2 and v3 sample count, mean CLV, normal
approximation 95% confidence interval, and mean exit CLV for each window. A window is
enabled for trading only after it has at least 50 positions and its 95% CI lower bound
is above zero.
